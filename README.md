# FoodLog Connect

レシート撮影から在庫管理・栄養診断・レシピ提案までを1つの流れにする、食のライフログアプリの試作品(プロトタイプ)です。

## 画面の役割分担

同じ情報を複数の画面に重複して置かないよう、次の役割で分けています。タブは「ホーム / 在庫 / お店 / 診断」の4つです。

- **ホーム＝概要**:何をすべきか(レシート撮影)と、ざっくりの現状(在庫の件数・品目のプレビュー、今月の食費・先月比)だけを表示。数字は在庫・お店タブと連動しており、タップすると詳細画面に移動します
- **在庫＝在庫の仕分け**:「冷蔵庫」(生鮮食品の残っている/消費済み)と「常備品」(醤油などの在庫あり/そろそろ切れそう)の2つ
- **お店＝購入データ**:「お店履歴」(よく行くお店の月別・日付別の購入履歴)と「価格の傾向」(カテゴリ別にどちらの店が安いか)の2つ
- **診断＝分析・提案**:栄養診断とレシピ提案

なお、レシートのOCR解析結果そのものは、ホームでスキャンした直後や「最後のスキャン」から開く一時的な画面で、タブには含まれません。

## 今のバージョンでできること

- 「レシートを撮影する」を押すと、解析中の演出のあと結果画面に切り替わります(ダミーデータ)
- レシート品目の鉛筆アイコンから、品目名をその場で修正できます
- 冷蔵庫の商品は「〇日前に購入」で表示し、賞味期限の推定はしません。各商品を「残っている」「消費済み」に自分で仕分けられます(ホームの在庫件数もこれと連動します)
- 生鮮食品とは別に「常備在庫」(醤油・オリーブオイルなど)のセクションがあり、購入日ではなく「在庫あり」「そろそろ切れそう」のシンプルな状態で管理します。ホームの在庫件数には含めません
- 「お店」タブの「お店履歴」では、Aスーパー・Bスーパー・Cスーパーの購入履歴を月ごとに集計して表示し、今月分には「今月」タグを付けて強調します。月の行(例:「2026年7月」)を押すと、その月だけの日付別の購入金額が展開されます
- Cスーパーのようにたまにしか使わないお店は、「価格の傾向に含める」を自分でオン/オフできます。オンにすると「価格の傾向」の比較にCスーパーも加わります(オフの間は集計に含まれません)
- 「価格の傾向」では、カテゴリ別(肉・魚/野菜・果物/乳製品・卵/米・パン・麺・調味料など)に、含める設定にしたお店の中でどこが安いかを確認できます。金額はダミーですが、「どちらが安いか」の判定は実際に計算しています
- 「今月」「先月」の合計を並べて表示するので、家計簿のように使うペースをぱっと確認できます(ホームの「今月の食費」もこの今月分の合計と連動します)
- 「診断」タブでは、一番のおすすめレシピを大きく1件表示し、「メイン料理」「副菜」「汁物」のボタンから他の候補を一覧できます。品目はすべて今の冷蔵庫の在庫(サーモン・ほうれん草・キノア・牛乳・卵・トマト)の組み合わせで作られており、各品目に「使用食材」を明記しています。野菜を含む品目には「おすすめ」バッジが付きます。各品目のリンクは、料理名ではなく使用食材で検索するようにしており、実際にクックパッドの検索結果が開きます(品目名自体はダミーですが、検索自体は本物です)
- 初回は「まだ記録がありません」という空の状態から始まり、一度スキャンすると通常表示に変わります(下部の「デモを初期状態に戻す」でリセット可能)

## まだ本物ではない部分

- レシート画像の読み取り(OCR)は行っていません。表示される品目・金額はすべて固定のダミーデータです
- 在庫やスキャン履歴はブラウザ内に一時保存されるのみで、サーバーやデータベースには保存されません
- レシピ詳細ページ・栄養診断の実データ連携は未実装です

## 使い方(確認方法)

このフォルダの `index.html` をブラウザで直接開くか、簡易サーバーで確認してください。

```bash
npx serve .
```

## 構成

- `index.html` … 画面構造(ホーム / レシート・在庫 / 栄養診断)
- `style.css` … 見た目のスタイル
- `app.js` … 画面切り替えや簡易的な操作(ビルド不要のプレーンJavaScript)
