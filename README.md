# FoodLog Connect

レシート撮影から在庫管理・栄養診断・レシピ提案までを1つの流れにする、食のライフログアプリの試作品(プロトタイプ)です。

## 画面の役割分担

同じ情報を複数の画面に重複して置かないよう、次の役割で分けています。タブは「ホーム / 在庫 / お店 / 診断」の4つです。

- **ホーム＝概要**:何をすべきか(レシート撮影)と、ざっくりの現状(在庫の件数・品目のプレビュー、今月の食費・先月比)だけを表示。数字は在庫・お店タブと連動しており、タップすると詳細画面に移動します
- **在庫＝在庫の仕分け**:「冷蔵庫」(生鮮食品の残っている/消費済み)と「常備品」(醤油などの在庫あり/そろそろ切れそう)の2つ
- **お店＝購入データ**:「お店履歴」(よく行くお店の月別・日付別の購入履歴)と「価格の傾向」(カテゴリ別にどちらの店が安いか)の2つ
- **診断＝分析・提案**:栄養診断とレシピ提案

なお、レシートのOCR解析結果そのものは、ホームでスキャンした直後や「最後のスキャン」から開く一時的な画面で、タブには含まれません。

## 今のバージョンでできること

- 「レシートを撮影する」を押すと、実際にスマホ/PCのカメラ(またはファイル選択)が起動します。撮影した写真はそのままレシート結果画面の背景に表示されます。ただし写真の中身を文字として読み取ってはおらず、表示される品目・金額は固定のデータです(実際に撮影されたレシート(ツルヤ徳間店、2026/8/23、27点・合計¥7,528)の内容を書き起こして反映しています)
- 在庫の仕分け(残っている/消費済み/在庫あり/そろそろ切れそう)、お店の名前変更・追加・価格傾向への含める設定は、ブラウザの保存機能(localStorage)に保存され、ページを再読み込みしても消えません。ただしこれは今開いているブラウザだけに保存される仕組みで、他の端末やアカウントとは同期しません。下部の「デモを初期状態に戻す」を押すと、保存内容を消して最初の状態に戻せます
- レシート品目の鉛筆アイコンから、品目名をその場で修正できます。修正すると在庫(冷蔵庫・常備品)側の商品名表示にも同じ内容が反映されます
- 在庫の表示は「納豆」「トマト」のような内容を大きく表示し、レシート上の商品名(「金のつぶたっぷりおだ」「森林そだち中玉」など)はその下に小さく補足として表示します
- 冷蔵庫の商品は「〇日前に購入」で表示し、賞味期限の推定はしません。各商品を「残っている」「消費済み」に自分で仕分けられます(ホームの在庫件数もこれと連動します)
- 生鮮食品とは別に「常備在庫」(醤油・オリーブオイルなど)のセクションがあり、購入日ではなく「在庫あり」「そろそろ切れそう」「消費」の3状態で管理します(ボタンを押すたびに順番に切り替わります)。ホームの在庫件数には含めません
- 冷蔵庫・常備品ともに、「消費済み」「消費」にしてから3日経った商品は在庫表示から自動的に消えます
- 冷蔵庫の商品は、献立を考えやすいように「野菜・果物→海鮮→肉類→その他」の順にまとめて表示し、カテゴリごとに色分けしています
- 「冷蔵庫」と「常備品」の振り分けは固定ではなく、品目名から自動判定しています(「醤油」「油」「味噌」などの調味料系キーワードを含む名前は常備品、それ以外は生鮮食品として冷蔵庫に振り分けられます)
- 「お店」タブの「お店履歴」では、Aスーパー・Bスーパー・Cスーパーの購入履歴を月ごとに集計して表示し、今月分には「今月」タグを付けて強調します。月の行(例:「2026年7月」)を押すと、その月だけの日付別の購入金額が展開されます
- Cスーパーのようにたまにしか使わないお店は、「価格の傾向に含める」を自分でオン/オフできます。オンにすると「価格の傾向」の比較にCスーパーも加わります(オフの間は集計に含まれません)
- お店の名前は鉛筆アイコンから自由に変更でき、「＋ お店を追加」から新しいお店を登録できます(価格の傾向への追加はCスーパーと同様、追加後に自分で選びます)
- レシート解析結果画面の店名は、登録済みのお店から選ぶプルダウンになっています。ここから新しいお店を追加することも可能です。選ぶお店を変えると、そのレシートの金額(¥2,010)がお店の購入履歴・今月の食費・価格の傾向のあいだで実際に付け替わります
- 「価格の傾向」では、カテゴリ別(肉・魚/野菜・果物/乳製品・卵/米・パン・麺・調味料など)に、含める設定にしたお店の中でどこが安いかを確認できます。金額はダミーですが、「どちらが安いか」の判定は実際に計算しています
- 「今月」「先月」の合計を並べて表示するので、家計簿のように使うペースをぱっと確認できます(ホームの「今月の食費」もこの今月分の合計と連動します)
- 「診断」タブの「あなたの食生活」は、直近1週間に「消費済み」(常備品は「消費」)にした商品をもとに、5大栄養素(タンパク質・脂質・炭水化物・ビタミン・ミネラル)のバランスを実際に計算して表示します。「在庫」タブで商品を消費済み/消費にすると、リアルタイムでグラフと注意書きが更新されます。まだ何も消費済みにしていない場合は、その旨を案内する空の状態を表示します
- 「診断」タブでは、一番のおすすめレシピを大きく1件表示し、「メイン料理」「副菜」「汁物」のボタンから他の候補を一覧できます。使用食材が1つも冷蔵庫に無いレシピはそもそも表示されず、今の在庫でより多くの食材が揃うものほど上に表示されます。今週の栄養診断で不足している栄養素(タンパク質・ビタミンなど)を補う食材を含むものだけに「おすすめ」バッジが付きます(在庫だけで作れても、不足栄養素と関係ないものはバッジなし)。冷蔵庫の状態が変わって作れるレシピが無くなった場合は、その旨を案内する空の状態を表示します。各品目のリンクは、料理名ではなく使用食材(+スープ/サラダ等の料理の種類)で検索するようにしており、実際にクックパッドの検索結果が開きます(考えた料理名自体はダミーですが、検索自体は本物です)
- 冷蔵庫・常備品・栄養診断・レシピ提案はすべて、レシート解析結果と同じ実際のレシート(ツルヤ徳間店、2026/8/23購入分・27点)の品目データから作られています。品目名から自動判定した冷蔵庫/常備品の振り分け、5大栄養素の判定、レシピの組み合わせが、すべてこの同じデータを元に一貫して連動しています
- 発表時などにその場でのカメラ撮影に失敗するリスクを避けるため、初めてこのブラウザで開いたときは「スキャン済み」の通常表示から始まります。スキャン前の「まだ記録がありません」という空の状態を見せたい場合は、下部の「デモを初期状態に戻す」から実演できます

## まだ本物ではない部分

- レシート画像の読み取り(OCR)は行っていません。カメラ撮影自体は本物ですが、そこから文字を読み取る処理はなく、表示される品目・金額はすべて固定のダミーデータです
- データはブラウザのlocalStorageに保存されるのみで、サーバーやデータベースには保存されません(端末をまたいだ同期はできません)
- レシピ詳細ページ・栄養診断の実データ連携は未実装です

## 使い方(確認方法)

このフォルダの `index.html` をブラウザで直接開くか、簡易サーバーで確認してください。

```bash
npx serve .
```

## 構成

- `index.html` … 画面構造(ホーム / レシート・在庫 / 栄養診断)
- `style.css` … 見た目のスタイル
- `app.js` … 画面切り替えや簡易的な操作(ビルド不要のプレーンJavaScript)
